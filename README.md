# esf-matcher

Подбор номенклатуры во входящих ЭСФ для «1С:Бухгалтерии для Казахстана, ред. 3.0».

В полученном ЭСФ (раздел G) поставщик пишет свои наименования, а колонка «Товар» пустая — пока её не заполнят, поступление не создать. Расширение подставляет позицию из справочника, подсвечивает уверенные и сомнительные строки и учится на том, что бухгалтерия уже сопоставила в прошлых ЭСФ.

Проект для Zhambyl Hub · Digital Taraz Hackathon 2026.

## Как устроено

Строка проходит слои по порядку, первый уверенный ответ останавливает конвейер:

1. **Память** — что эта бухгалтерия уже выбирала для этого поставщика (`src/match/memory.js`).
2. **Точное совпадение** после нормализации единиц, фасовки и сокращений (`src/normalize.js`).
3. **Нечёткое** — токены, триграммы, бренды; размер и цвет — жёсткий фильтр (`src/match/attrs.js`, `src/match/pipeline.js`).
4. **Модель ИИ** на остаток — следующий этап, интерфейс слоя заложен.

Малый отрыв между кандидатами — строка не заполняется, а уходит человеку. Главная метрика — тихие ошибки (неверная подстановка без предупреждения).

## Замер

```bash
node src/run-bench.js
```

## Состав

- `src/` — эталонная реализация движка и стенд на JavaScript (Node 18+, без зависимостей).
- `src/1c/` — порт движка на встроенный язык 1С (`.bsl`); проверка в казахстанской конфигурации впереди.
- `tools/onec.ps1` — пакетные операции с учебной платформой 1С; `tools/scan_config.py` — поиск документов с номенклатурой в выгрузке конфигурации.
- `PLAN.md` — инженерный план расширения.
- `pitch/` — презентация: `index.html` (листание ← →, H — справка), PDF — `pitch/esf-matcher-pitch.pdf`, план и речь — `pitch/PLAN.md`.
