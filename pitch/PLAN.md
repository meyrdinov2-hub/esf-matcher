# Питч: подбор номенклатуры во входящих ЭСФ

**Для чего:** проект — защита на Zhambyl Hub · Digital Taraz Hackathon (жюри, ~5 минут).
Сдаётся PDF (≤ 10 МБ) + ссылка на GitHub-репозиторий.

**Главная мысль:** не «ИИ-бухгалтер вообще», а одна узкая ручная операция, у которой
есть работающий прототип и замер: колонка «Товар» в полученном ЭСФ.

**Стиль «Сверка»:** тёмная бухгалтерская книга — чернильно-зелёный фон с линовкой,
бумажный текст, три цвета статусов строки из самого продукта:
зелёный — подобрано, янтарный — проверить, коралловый — не найдено.
Шрифты: Unbounded (заголовки), Golos Text (текст), JetBrains Mono (цифры, строки ЭСФ).
Фотографий нет сознательно: главный визуал — сами строки ЭСФ.

**Правило цифр:** все проценты — из одного прогона `node src/run-bench.js`
(seed 20260819, 6 документов, 92 строки, порог 0,75; память — 138 строк прошлого периода).
Данные синтетические, это подписано на слайде. Цифры конкурентов — с источником.

---

## 1. Колонка «Товар» заполняется сама
- **Экран:** кикер хакатона; заголовок; подзаголовок про расширение для «1С:Бухгалтерии для Казахстана»; строка ЭСФ → позиция справочника с зелёной меткой; плейсхолдер команды.
- **Визуал:** анимированная строка «ГЕЛЬ FREYA… 450МЛ» → «Средство для мытья рук Чистозря».
- **Речь (30 с):** «Мы делаем расширение для 1С:Бухгалтерии для Казахстана. Оно закрывает одну конкретную ручную операцию — подбор номенклатуры во входящих счетах-фактурах. Посмотрите на эту строку: поставщик прислал гель для посуды, а бухгалтерия у себя всегда учитывает его как жидкое мыло. Ни одна модель этого не угадает. Наша система — угадывает, потому что учится на истории самой базы».

## 2. ЭСФ загружен. Колонка «Товар» пустая
- **Экран:** таблица раздела G с пустой колонкой; подпись: пока колонка пуста, поступление не создать; оценка «Первого БИТа»: 10 ЭСФ в день ≈ 1 час.
- **Речь (35 с):** «Получить ЭСФ в 1С уже не проблема — для этого есть штатный сервис. Проблема дальше. В разделе G поставщик пишет свои названия, а колонка "Товар" — пустая. Пока её не заполнили, документ поступления не создать. Бухгалтер подбирает строку за строкой вручную. По оценке Первого БИТа, обработка десяти ЭСФ в день занимает около часа. Сколько из этого — именно подбор номенклатуры, мы измерим на пилоте».

## 3. Половина строк не решается по тексту
- **Экран:** три раскрывающиеся карточки — «корзина», «своя логика», «нет в справочнике»; вывод: ответ — в истории вашей базы.
- **Речь (40 с):** «Мы разметили строки по сложности. Часть легко сопоставить по тексту. Но есть три класса, где текст бессилен. Корзина: сок, йогурт и сыр уходят в одну позицию "Продукты питания". Своя логика: гель для посуды — это мыло, просто потому что так решили в этой бухгалтерии. И позиции, которой нет вовсе, — тут правильный ответ "не знаю". Ключевая идея: историю не нужно копить. Сотни проведённых ЭСФ с заполненной колонкой уже лежат в базе клиента. Один прогон — и система работает с первого дня».

## 4. Как работает
- **Экран:** конвейер «память → точное → нечёткое → модель ИИ (на остаток, следующий этап)»; три цвета результата; принцип «лучше уточнить, чем ошибиться»; всё внутри 1С.
- **Речь (40 с):** «Строка проходит слои по порядку. Сначала память — что эта бухгалтерия уже выбирала для этого поставщика. Потом точное совпадение. Потом нечёткое: нормализуем единицы и фасовку, а размер и цвет считаем жёстким фильтром — поло XL никогда не станет поло M. Первый уверенный ответ останавливает конвейер. Если между кандидатами малый отрыв — строка становится жёлтой и уходит человеку. Языковую модель подключим на остаток. Всё работает внутри 1С: данные бухгалтерии никуда не уходят».

## 5. Замер на стенде
- **Экран:** три столбца — 0 % / 47,8 % / 77,2 % подобрано автоматически, 0 тихих ошибок; врезка «своя логика: 0 из 6 → 5 из 6»; подпись про синтетику.
- **Речь (40 с):** «Мы проверяем не "сколько угадали", а "сколько ошиблись молча". Это главное число, и оно ноль во всех сценариях. Без памяти правила подбирают 48 % строк. С памятью из прошлого периода — 77 %. Строки "своей логики": было 0 из 6, стало 5 из 6. Честно: это синтетика из нашего генератора с эталоном, 92 строки. На реальных документах цифры будут другими — их и покажет пилот».

## 6. Кто уже есть на рынке
- **Экран:** таблица: штатный «1С:ЭСФ для Казахстана», доработка «Первого БИТа», BuhGPT; наш фокус — подсказка для новых наименований, обучение на истории за один прогон, метрика тихих ошибок.
- **Речь (35 с):** «Аналоги есть, и мы их изучили. Штатный сервис 1С забирает ЭСФ. У Первого БИТа есть доработка, которая создаёт поступления; номенклатуру там сопоставляют вручную и затем запоминают по поставщику. BuhGPT отвечает на вопросы бухгалтера — это другая задача. Наш фокус — строки, которые раньше не встречались, и запуск сразу на истории базы. Превосходство не заявляем: сравним на одних и тех же документах».

## 7. Как докажем экономию
- **Экран:** формула; пять метрик пилота; шаблон «до / после» с пустыми ячейками; модель оплаты — гипотеза.
- **Речь (30 с):** «Быстро сгенерировать — не значит сэкономить. Если бухгалтер потом всё исправляет, пользы нет. Поэтому считаем полное время: проверку жёлтых строк и исправления тоже. Таблица "до и после" пока пустая — мы заполним её на пилоте, а не на слайде. Модель оплаты — гипотеза: внедрение и подписка по числу организаций».

## 8. Что готово и что просим

- **Речь (35 с):** «Движок и стенд готовы, порт на встроенный язык 1С написан. Дальше — учебная конфигурация для Казахстана, регистр памяти, кнопка в форме ЭСФ. Нам нужен партнёр 1С и одна бухгалтерия для пилота: обезличенные ЭСФ, тестовая база и бухгалтер, который оценит результат. В Таразе есть официальный партнёр 1С — Азия Сервис. Договорённостей пока нет, мы предлагаем обсудить пилот. Следующим процессом станут банковские выписки».
